## 1) 专业视角：一份基于 Django 的技术文档应包含哪些内容

1. **文档控制信息**

   * 版本记录、适用范围（MVP/V1/V2）、读者对象（FE/BE/QA/运维）、术语表、非目标（Out of scope）

2. **系统总体设计**

   * 业务目标与核心场景、模块边界、关键约束（性能/安全/一致性/多租户）、核心用户路径（端到端流程图）

3. **技术架构与部署拓扑**

   * 组件划分（Django/DRF、DB、调度、执行引擎、分析存储、缓存等）、数据流/请求流、部署形态（单体/拆分）、环境划分（dev/stg/prod）

4. **代码组织与工程规范（Django 特有）**

   * apps 拆分、分层（views/serializers/services/repos）、依赖与配置（settings 分层）、统一错误码/响应体、日志规范、权限/中间件位置与职责

5. **数据架构与模型设计**

   * 元数据表 ERD、关键字段字典、索引策略、迁移策略（migrations）、软删除/审计字段、与“物理表/分析表”的映射规则

6. **认证、租户与权限体系**

   * JWT/Session、TenantContext 中间件、TenantUser 状态机、RBAC（资源权限）、行/列权限计算与合并规则、权限在 API 层/Service 层的落点

7. **接口设计规范（最重要）**

   * 逐接口：URL/Method、入参（含校验/默认值）、出参（含字段含义）、分页/排序、错误码、幂等性、并发与锁、权限前置条件、审计记录要求

8. **核心业务模块设计（按模块拆章节）**

   * 每模块：核心概念、页面/交互对应的后端能力、状态机、关键校验、事务边界、与其他模块的联动、异常与降级

9. **异步任务、调度与执行引擎**

   * Celery/队列、cron 解析、并发控制、重试策略、任务幂等、运行记录/节点日志结构

10. **可观测性与运维**

* 结构化日志、审计日志、指标与告警、链路追踪、运维 Runbook（常见故障处理与定位）

11. **性能与容量**

* 慢查询治理、缓存策略、批处理策略、限流与配额、关键接口 SLA

12. **测试与验收**

* 单元/集成/E2E、测试数据构造、契约测试、验收用例与回归清单

## 2) 基于你这份「建模 + Flow + BI」PRD，技术文档目录（含每章应写什么）

> 下方目录按「上面第 1 部分的技术文档要求」组织，并结合 PRD 的**明确行为/约束**落到可开工粒度；每章建议都写到“接口级 + 校验级 + 事务级”。

### 0. 文档控制信息

* 版本记录、适用版本（V1）、模块范围：建模 / 任务流 / 报表（数据集/可视化查询/仪表盘）与术语定义（Chart/Dashboard/DashboardItem/DSL/LLM 等） 

### 1. 系统总体概述

* 端到端主链路（建模建表 → Flow 写入/加工 → 数据集沉淀 → 分析出图 → 仪表盘消费）
* 典型场景（主表-明细表关联字段，Join 条件推荐逻辑） 

### 2. 技术架构与组件拆分

* Django/DRF 分层：Middleware（TenantContext）/Auth/Permissions/Views/Service/Repo
* 存储划分：元数据存储 vs 业务物理表 vs 分析存储（Dataset 落库表）
* 三条关键链路架构图：

  * 请求链路（认证/租户/权限）
  * 执行链路（FlowRun/NodeRun）
  * 查询链路（Dataset → Chart 查询 → Dashboard 组合）

### 3. 工程结构与编码规范（Django）

* apps 划分建议：tenants、iam、resource_tree、modeling、flows、datasets、charts、dashboards、audit、adapters
* 统一响应体/错误码/分页约定（放“接口规范”章节里强约束）
* 配置与环境变量（DB 连接、分析存储、ollama、队列等）

### 4. 跨模块公共能力设计

#### 4.1 租户与登录态

* Tenant ACTIVE/SUSPENDED、TenantUser DISABLED 的统一拦截策略（放在中间件/认证层）
* request_id 注入与贯穿日志

#### 4.2 资源树与授权（Folder 默认权限、资源节点显式覆盖）

* 表/Flow/Dataset/Dashboard 的资源树组织与权限继承、合并规则 
* **重要约束**：Dataset 与 Dashboard **不共用同一棵资源树** 

#### 4.3 行/列权限与 FilterDSL

* 列权限合并、HIDDEN/READONLY/READWRITE 的接口行为（查询不返回、前端不展示、强校验） 
* FilterDSL 的 JSON 结构、校验器、SQL 生成策略、注入防护（必须写清）

## 5. 建模模块（Modeling）技术设计

#### 5.1 模块入口与前置规则

* 进入条件与“无任何表权限时的空态处理” 
* 租户停用/用户禁用的统一处理

#### 5.2 核心数据模型与字典

* Table、Field、关联字段（ref_table/ref_field/ref_display_field）、系统字段
* 系统字段清单与不可编辑规则 

#### 5.3 表的创建/编辑/删除（含事务边界）

* **事务性要求**：元数据写入 + 物理建表必须整体成功/回滚 
* 并发编辑（updated_at 乐观锁）策略 
* 删除策略（软删/引用检查/物理表处理：按你的 PRD 约束落地成“必须怎么做”）

#### 5.4 字段管理（类型、校验、变更限制）

* 字段类型不可变更、关联字段配置必填项、从普通迁移到关联的“新增+迁移”流程 
* “可空→必填”的数据校验规则与错误提示 

#### 5.5 编码体系与 LLM 生成（table_code/field_code）

* code 生成流程、唯一性范围、失败降级、**创建后不可修改**  

#### 5.6 建模模块 API 清单（逐接口落表）

* “生成编码”“建表”“加字段”“改字段”“数据页 CRUD”“引用检查”等：每个接口写入参/出参/校验/权限/错误码/审计

---

## 6. 任务流模块（Flows）技术设计

#### 6.1 模块目标与权限边界

* Flow 的定位、触发方式、可观测要求 
* **关键约束**：Flow 执行按全表处理，**不叠加行/列权限**（只受资源级权限约束） 

#### 6.2 数据模型与状态机

* Flow、Node、Edge、FlowRun、NodeRun（字段含义、索引、状态流转）
* NodeRun 核心字段（row_count、error_message、extra_info） 

#### 6.3 节点类型与配置规范

* TABLE_SOURCE/…/JOIN/…/TABLE_SINK：配置项、校验器、SQL 生成策略、运行期输入输出约定
* TABLE_SINK 写入模式语义与事务回滚要求 

#### 6.4 运行前校验（保存/运行统一校验）

* DAG 无环/无孤立、必填配置、JOIN 上游、SINK 字段映射覆盖、权限校验 

#### 6.5 调度与并发控制

* cron + 时区配置、错过执行不补跑规则 
* 同一 Flow 同时只能 1 个 RUNNING，调度触发跳过策略 

#### 6.6 Flow API 清单（逐接口）

* Flow CRUD、DAG 保存、运行一次、运行记录查询、日志拉取、调度配置、权限配置

## 7. 报表模块（BI）技术设计总览

> 报表模块至少拆成：Dataset（数据资产层）→ 可视化查询/Chart（分析工作台与资产化）→ Dashboard（高频消费）

---

## 8. 数据集模块（Datasets）技术设计

#### 8.1 模块定位与目标

* Dataset 是“数据资产层”，需要**落库到分析存储**，查询基于数据集表 
* 创建时固化范围快照，避免隐式扩权/口径漂移 

#### 8.2 Dataset = 元数据配置 + 物理落库表（映射规则）

* 物理表命名、分区/索引建议、字段同步策略、与源表变更的影响处理 

#### 8.3 状态机与刷新机制

* DRAFT/ACTIVE/REFRESHING/FAILED/BLOCKED/PAUSED 的流转与 UI/接口含义 
* 同一数据集禁止并发刷新、刷新日志结构与错误可解释性

#### 8.4 创建与编辑向导（后端校验逐条落地）

* 来源表可选范围（TABLE_DATA>=VIEW）、字段列表隐藏规则（HIDDEN 不可见） 
* base_filter 保存、影响分析、引用保护（被引用不可删）

#### 8.5 Dataset API 清单

* CRUD、刷新（首次/手动/定时）、刷新日志、引用检查、Owner 转移/阻断恢复

---

## 9. 可视化查询与图表（Charts）技术设计

#### 9.1 模块定位与核心概念

* 基于数据集的交互式分析；Chart = query_config + viz_config（不含布局） 

#### 9.2 图表资产化（列表，不做树）

* 列表字段、筛选/搜索、详情/复制/删除入口 

#### 9.3 权限规则与字段变更影响

* 进入分析前置：DATASET>=VIEW；缺数据集权限的占位降级 
* 删除图表：仅 DATASET>=MANAGE；字段被移除导致图表错误态提示 

#### 9.4 导出与查询执行

* 导出 CSV/PNG、导出权限、查询超时/限流、缓存策略（如有）

#### 9.5 Charts API 清单

* 预览查询、保存 Chart、加载/编辑/复制/删除、导出

---

## 10. 仪表盘（Dashboards）技术设计

#### 10.1 模块定位与目标 & 明确不做

* 独立资源树；编辑器拖拽布局；联合校验；异常降级；自动刷新 
* **V1 不做**：全局筛选、整盘导出 

#### 10.2 信息架构与资源树

* scope=DASHBOARD 的 Folder/Item、树与列表字段、状态摘要要求 

#### 10.3 刷新机制（手动/自动）

* 自动刷新开关权限、间隔枚举、行为与后台降频策略 

#### 10.4 全局筛选（V1 固定关闭）

* filters_json 为空、入口隐藏、前后端字段固定 

#### 10.5 仪表盘 API 清单

* CRUD、布局保存、添加/移除图表实例、刷新、分享（如 PRD 有）、权限配置、导出（若仅图表级导出）
